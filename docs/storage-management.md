# 存储管理（1.7.3）

后台入口是「源站运营 → 存储管理」。原来源站设置里的收费仓库和发布仓库不再单独配置。

## 以前两个都填时怎么走

这两处互不兜底：

- 收费仓库（`github_paid_*`）只给收费安装包。配了就只上传到这一枚 GitHub 私有仓库，失败不改存本站，也不改用发布仓库。没配时收费包暂存在本站。
- 发布仓库令牌只能选 GitHub 或 Gitee 其中一套。只在勾选推送 Release 时使用，免费包推到该仓库并保存公开地址。不用于收费包。
- 表单是单选。从 GitHub 改成 Gitee 会覆盖同一条发布仓库记录，不会同时留下两套发布仓库。

## 升级后怎么迁移

第一次读取存储列表时自动迁移，不用重新粘贴令牌：

- 收费仓库有所有者、仓库和令牌时，成为主存储。
- 发布仓库已经配齐时，成为另一条。前面已经有启用的位置时它是备用，否则它是主存储。
- 令牌重新加密后写入存储列表。旧字段仍保留，旧的上传和发布路径还能读。在存储管理里改一条带旧标记的位置时，会写回对应的旧字段。

## 分片阈值

按各存储公开文档的单文件上限，不把 Git 对象的 100MB 限制套到 Release 附件上：

| 存储 | 文档上限 | 实际上传分片 |
| --- | --- | --- |
| GitHub Release | 每个附件小于 2 GiB | 2 GiB 减 1 MiB |
| Gitee 发行版 | 单个附件不超过 100 MB | 95 MiB，给 multipart 边界留余量 |
| 阿里云 OSS、腾讯云 COS、Cloudflare R2、MinIO（S3 PutObject） | 5 GiB | 5 GiB 减 1 MiB |

超过分片大小时自动切开，旁边放一份清单。下载时按清单拼回原文件，再核对 sha256。目录压缩包本身仍有 20 MiB 上限，正常目录上传不会碰到这些阈值。

## 下载

买家不拿到含仓库路径的地址。GitHub 和 Gitee 仍由本站取回并核对校验码。S3 兼容存储且未分片时，可以跳到短时签名地址。管理员下载优先用签名地址，否则用本站几分钟内有效的票据。

不接百度网盘和阿里云盘。
