# 安全说明

本文写给购买和运维 auth-pro 的人，说明 **1.6.0** 里已经落地的控制，以及仍要由操作者承担的事项。发现这些问题时的记录在 [P0/P1 审计](audit/p0-p1-2026-09.md)，那份文档描述的是 v1.5.0 当时的代码，不是当前漏洞清单。

## 已落地的控制

| 项目 | 当前行为 |
| --- | --- |
| 安装锁 | 存在 `install.lock` 时，安装写接口直接 403。锁不在，但库里已有管理员或业务数据时，初始化表和创建超级管理员也会 403，避免只删锁文件就接管 |
| 余额购买 | 用户和代理扣款在同一事务里按「余额减去本次金额」更新，扣款未成功不发授权 |
| 公开校验 | 按客户端 IP 与 `appKey` 每分钟最多 1200 次。签名未通过时，应用不存在和签名错误对外是同一句「授权校验失败」 |
| 首页授权查询 | 未登录返回 401。登录后只返回自己的授权 |
| 管理员会话 | 访问令牌约 24 小时。`refreshToken` 带 `typ=refresh`，有效期 7 天，不能当作访问令牌。管理员被禁用，或角色与令牌不一致时，旧访问令牌失效 |
| 代登录 | 仅超级管理员。令牌 2 小时，写入操作日志，不改被代登录账号的最后登录信息 |
| 菜单权限 | 管理端敏感写接口使用 `RequireMenu`。没有对应菜单的管理员不能只凭后台 JWT 调用。超级管理员放行 |
| 数据库口令文件 | `db.json` 按 `0600` 保存，启动时收紧过宽权限 |
| 在线更新 | `package.signature` 必须是 `sha256:` 加包的 SHA256，并核对 GitHub Release 附件 digest。前端目录先写入暂存再改名。默认不信任历史 Gitee 仓库 |
| 插件安装 | 远程包必须带 SHA256，不一致则不安装。公网必须 HTTPS。字面量私网源才允许 HTTP 和私网。源站外链在下载前拒绝私网、链路本地和云元数据地址 |
| 付费外链拉取 | 付费条目的 HTTPS 外链由本站拉取后写入私有目录。只允许 HTTPS，限制大小、超时和重定向次数，并拒绝内网、回环、链路本地和云元数据地址（含重定向后的地址和 DNS 解析结果）。买家目录和下载链接不包含这条外链 |
| 源站迁移 | 破坏性结构变更记入 `schema_migrations`。失败不标记为已应用，启动失败，避免每次启动丢列 |
| 授权状态 | 授权被禁用或重新启用且状态确有变化时，持有人收到站内通知 |

盗版告警中心没有接上的通知开关。校验失败不会自动写告警，也不会自动发邮件或 Webhook。

## 操作者必须自己做的事

- 备份 `db.json`、`install.lock`、`jwt.secret` 和 MySQL。升级脚本会拷贝这些文件；在线更新只有在勾选备份时才导出 SQL。两者都代替不了你自己的异地备份。
- `jwt.secret` 在数据目录，由进程在缺失时生成。泄露或换掉该文件会使已签发的登录态失效或被伪造。权限保持 `600`，不要放进网站可下载目录。Nginx 必须拦截 `/backend/`、`db.json`、`install.lock`、`jwt.secret`，见 [部署手册](deployment.md)。
- `db.json` 里是数据库口令。同样不要通过 Web 提供下载。
- `appSecret`、支付商户密钥、源站仓库 Token、邮件 SMTP 密码只放在服务器。SDK 浏览器包故意不包含 `appSecret`。
- 进程守护的运行目录必须是 `backend/`，启动命令必须是 `backend/start.sh`。1.5.7 起，在线更新会退出并交给守护拉起。手工替换程序，或用 `baota-upgrade.sh --no-start` 时，仍要先在守护里停止，避免旧进程占着 `19127`。
- 软件源若填写内网地址，表示你信任该源。服务端会拉取清单和包。
- 静态首页模板跑在 iframe 沙箱里，但仍可能执行包内脚本。只启用审核过的模板。

## 更新包信任边界

SHA256 与 Release digest 能发现下载损坏和清单被单独改掉。若 GitHub 仓库的发布权限本身被攻破，攻击者可以同时换掉包和摘要。重要环境应在更新前核对 Release 来源，并保留 `baota-upgrade.sh` 生成的备份以便手工还原。
