# 审核之后

## 条目状态

开发者列表与管理端「软件目录」使用同一组状态：

| 状态 | 界面 | 开发者能否改包 |
| --- | --- | --- |
| `draft` | 草稿 | 能 |
| `rejected` | 已驳回 | 能，可再次提交 |
| `review` | 待审核 | 不能改已提交的包，等管理员处理 |
| `approved` | 已通过 | 换包走新版本 |
| `published` | 已上架 | 换包走新版本 |
| `hidden` | 已下架 | 公开目录不再列出 |
| `deprecated` | 已弃用 | 公开目录不再列出 |

驳回说明显示在登记抽屉里。入驻申请是另一条流程：未通过时不能使用开发者面板登记。

第三方（`developer_id > 0`）价格大于 0 的条目仍不能上架，错误仍是「付费条目暂不能上架，购买与交付将在后续版本开放」。源站管理员自己的条目（`developer_id = 0`）可以用本站托管 ZIP 或内置交付上架。公开目录里的付费行不带 `downloadUrl`、`templateUrl` 或 `sha256`，只保留 `priceCents`。商业版用户安装这些官方付费包，见 [商业版](../commercial.md)。

## 管理员

在「源站运营 → 软件目录」通过、驳回、上架、下架、弃用，或编辑名称、简介、分类、地址、SHA256。`id` 创建后不能改。所属应用可以用「切换应用」改到另一个现存应用，支持勾选多条。版本、价格和安装包跟着走，并写入审计。目标应用里已经有相同标识时会拒绝。

应用下拉里的「未归属（应用已删除）」列出 `app_id` 对不上任何现存应用的条目，可以再绑回去。删除应用时如果下面还有目录条目，后台会要求先迁移到其他应用。

开发者在自己的列表里同样可以切换应用，但只能动自己的条目，目标只能是登记时能选到的应用。

上架、下架、弃用、审核状态变化，以及已上架条目的元数据或 latest 变化之后，会重建该应用的公开清单：

```text
GET /software-source/{app_key}/index.json
```

插件出现在 `plugins`，模板出现在 `homeTemplates`。弃用后的条目会从这两份列表里去掉。

「公开目录」可以预览这份 JSON，并手工从数据库重生快照。

## 下架不是远程卸载

下架只是公开清单里不再出现。其它授权站已经下载安装的插件或模板不会被删掉，也不会被远程停用。
