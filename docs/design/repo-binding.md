# 仓库绑定（设计，确认前不写代码）

每个应用只绑一个私有仓库。仓库里用固定的五个位置分开存放，免费和收费、客户安装包和插件模板互不混放。本站程序自己的在线更新不进这个设置。开发者端不挂导入接口。令牌只用「存储管理」里已经加密保存的那一枚，页面不出现第二套密钥，也不回显明文。

确认这张设计和效果图之前，不改正式界面，也不改绑定相关的后端。

## 不在这个模块里

- 不配置本站程序的在线更新。它继续走现在的来源，页面上没有入口。
- 不调用删除远程仓库的接口。解绑、换绑、迁移都不会删仓库。
- 不在页面上预填或写死某个固定的所有者/仓库名。站长自己的仓库名可以显示，因为那是他刚绑定的。
- 不把令牌、密钥写进审计、下载地址或开发者能看到的文案。
- 不给开发者挂导入接口。开发者上传仍由系统用站长令牌写入该条目所属应用的仓库。外链拉取仍只走公开 HTTPS，不带站长令牌。
- 对象存储和网盘继续做存储管理里的主备副本，不另绑第二套「每个应用一个桶」。绑定的权威位置是这一枚私有仓库。

## 和现有能力怎么接

| 现有 | 绑定之后 |
| --- | --- |
| 存储管理里的 GitHub 位置和加密令牌 | 绑定只记录用哪一个位置。轮换令牌仍在存储管理完成 |
| 已有的「测试令牌、识别所有者、缺仓库则建私有库、公开库拒绝」 | 绑定沿用这套判断和中文错误，去掉其中的固定仓库名和令牌申请网址 |
| 存储检查 | 同一页增加「仓库绑定」结果，不新开监控页，不出问题时不改上下架 |
| 源站审计 `source_audit_logs` | 绑定、换绑、解绑、迁移、改价搬移各写一条。不另建审计表 |
| 发布版本 / 插件 / 模板的「从仓库导入」 | 去掉手填仓库。只读该应用已绑定的仓库和对应位置 |
| 安装包对象键 `github:所有者/仓库/标签/附件` | 标签改成带位置前缀。校验通过之后才改数据库里的键 |

GitHub 驱动存的是 Release 附件，不是 git 目录树。五个名字在界面上仍写成 `client/`、`plugins/free/`、`plugins/paid/`、`templates/free/`、`templates/paid/`。落到仓库时是发布标签的前缀，不是一次提交进五个文件夹。对象存储上的副本用同样的五段键前缀。这样换驱动时不用再改一遍规则。

## 数据

一张绑定表，一个应用一行：

- `app_id`
- `location_id`：存储管理里的 GitHub 位置，令牌从那里解密
- `owner`、`repo`、私有标记
- 状态：`ready` 或 `degraded`（令牌失效、仓库不可读）
- 绑定时间、更新时间

没有令牌列。

已发布对象的地址本身带所有者、仓库和标签。换绑时若选择「只切换」，旧地址不动，下载仍指向旧仓库；新的导入和上传写入新仓库。选择「迁走」时，新地址核对一致之后才替换旧地址。

归档应用不自动解绑，也不删仓库。已归档应用不能作为新的绑定目标。

## 五个位置

| 界面名称 | 标签前缀 | 放入 |
| --- | --- | --- |
| client/ | `client/` | 该应用的客户安装包和 `latest.json` |
| plugins/free/ | `plugins/free/` | 免费插件 |
| plugins/paid/ | `plugins/paid/` | 收费插件 |
| templates/free/ | `templates/free/` | 免费模板 |
| templates/paid/ | `templates/paid/` | 收费模板 |

标签形如 `plugins/paid/demo-plugin-1.0.0`，附件名保持 `{标识}-{版本}.zip`。对象键是 `所有者/仓库/plugins/paid/demo-plugin-1.0.0/demo-plugin-1.0.0.zip`。

`latest.json` 增加 `appKey`（例如 `app_f93896d80066_5811`），不用数据库数字编号。多出来的字段不影响只认原有字段的客户程序。导入端必须读到与当前应用一致的 `appKey`。

初始化不为了「摆出空目录」去传一个假附件。五个位置先记在绑定上，第一次写入才产生对应发布。

## 创建应用

创建应用在现有弹窗里增加第 2 步「仓库」。第 1 步仍是现在的应用名称、授权方式、回调、状态和备注。编辑已有应用不出现这一步，改仓库去「仓库绑定」。

第 2 步三个选择：

1. 自动创建私有仓库。名称按刚填的应用名预填，可以改。
2. 绑定已有仓库。填写 `所有者/仓库`，必须已存在且是私有的。
3. 稍后绑定。应用先建好，仓库留空，之后在「仓库绑定」里补。

默认值：

- 存储管理里有一枚可用的 GitHub 令牌：选中「自动创建私有仓库」。
- 没有令牌、令牌无效或已过期：选中「稍后绑定」。自动创建和绑定已有都不可选，并说明「还没有可用的令牌，请到存储管理添加。也可以先创建应用，稍后再绑定。」

仓库名规则：只允许字母、数字、点、下划线和连字符。应用名本身符合规则时，预填为小写并把空格改成连字符，例如 `Customer Portal` 成为 `acme/customer-portal`。应用名是中文或其它无法直接使用的字符时，预填 `所有者/app-` 加上即将生成的应用标识短码，并说明可以改成自己的名字。用户改过输入框之后，再改应用名不再覆盖。

同一次提交按这个顺序做完，不拆成后台任务：

1. 先校验应用信息和仓库选项。名称不合法、或选了已有仓库却没填，都不创建应用。
2. 写入应用并生成 `appKey`。
3. 选「稍后绑定」：到此结束。应用未绑定，这不是失败，结果里只提示可以稍后绑定。
4. 选「自动创建」或「绑定已有」：仓库创建或确认成功后，立刻写入绑定和五个位置。五个位置只记在绑定上，不上传空文件。
5. 第 4 步任何失败：应用保留，绑定不写。不删除已经在远程出现的仓库。结果说明原因，并给出重试。

重试绑定的是刚创建的这一条应用，不会再创建一次应用。若远程仓库其实已经建出来、只是绑定没写上，重试默认改到「绑定已有仓库」，名称填刚才那一个。

重试入口同时出现在三处：创建结果上的「重试绑定」、应用列表该行的「绑定仓库」、仓库绑定列表里的同一条未绑定记录。只弹一条提示不够。

点「去存储管理」会离开创建页，已填内容不保留。也可以先选稍后绑定，添加令牌后再从上述入口重试。

## 绑定

入口在「源站运营 → 仓库绑定」，也承接创建时跳过或失败后的重试。发布版本页只显示已绑定的仓库，并链到这一页。

步骤：

1. 选择应用。一个应用一行，显示未绑定、正常或异常。
2. 令牌。显示「使用存储管理中的 GitHub 主存储，密钥已保存」。没有可用的 GitHub 位置时，停在这一步，按钮去存储管理。本页不能粘贴新令牌。
3. 校验令牌和权限。沿用现有结果：无效或过期、无法连接、权限不足。权限不足时，若仓库已经存在且是私有的，仍可绑定；仓库不存在则不能创建，停下来说明原因。
4. 仓库名。可手填 `所有者/仓库`。所有者只能是令牌账号或其组织。留空时，「生成默认名」填入 `所有者/app-` 加上该应用标识的短码，只填进输入框，此时还不创建。创建应用时的预填规则见上一节。
5. 检查仓库。不存在且有创建权限：说明将创建私有仓库。已是私有：直接用。已是公开：拒绝。没有权限：拒绝并说明。
6. 确认后创建（如需要）并记下五个位置。成功只表示绑定完成，不表示里面已有文件。

失败时不写绑定行。创建仓库成功但保存绑定失败时，不删远程仓库，页面说明仓库已在远程，可以再次绑定同一个名字。

客户站如果存储管理里已经有一个收费仓库、而应用都还没绑定：列表上方说明「现有安装包还在存储管理的主存储里，不会自动拆给每个应用」。站长点某个应用后再选择迁入或新建。升级时不批量建库。

## 更换

先出预览，再选一种做法。预览按五个位置列出件数和体积。加载中、没有文件、列不出远程这三种都要单独显示。

- 只切换。新的导入和上传改走新仓库。已经发布的地址仍指向旧仓库，下载不断。预览写明「这些已发布文件不会移动」。
- 迁走。按下面的「复制、核对、再改记录」把对象复制到新仓库的同一位置。

不允许在核对完成前删除旧文件。核对失败则新仓库里多出来的半截对象留在远程，绑定和目录地址都保持原样，审计记下失败。核对成功后，旧文件仍留在旧仓库，另有一次单独确认才删除旧副本。删不掉时绑定已经指向新地址，存储检查记一条提醒，不回滚价格或版本。

## 解绑

先做影响检查，数字来自目录和版本行，不靠猜测：

- 已发布、且地址落在这个仓库里的版本数（这些版本的下载靠它）
- 未发布的草稿数
- 最近导入、上传是否写过它

已发布版本数大于 0：解除绑定不可用。只提供「先迁到新仓库」和「取消」。若只弹出警告仍允许解除，已发布的下载会立刻找不到文件。

没有已发布版本、但有草稿：警告后可以解除。草稿留在远程，本地不再把新文件写进去。

没有任何依赖：可以解除。远程文件保留。

两种结果都没有「删除远程仓库」。绑定行删掉或标成未绑定，远程仓库不动。

## 令牌轮换和过期

轮换只在存储管理里替换那一枚加密密钥。绑定页显示位置名称、已保存、最近一次检查时间，以及「到存储管理更新令牌」。

令牌失效或过期时，该位置下的每个绑定在存储检查里变成异常，状态记为 `degraded`。不自动解绑，不改目录上下架。更新令牌后点「立即检查」，恢复则回到 `ready`。

## 存储检查

不新做一页「系统监控」。现有「存储检查」增加一组「仓库绑定」：

- 仓库还在，且是私有的
- 令牌还能列出发布
- 已登记的安装包还能按对象键找到
- 对象的位置前缀和它的种类、免费或收费一致

出问题只提醒。立即检查沿用现在的按钮。

## 免费和收费互换

改价时按种类选另一侧位置，例如 `plugins/free/` 与 `plugins/paid/`。

1. 先把文件复制到目标位置。
2. 核对校验码。
3. 不一致则改价取消，地址不动。
4. 一致后才更新版本行上的地址，并完成改价。
5. 再删旧位置上的文件。删失败不影响改价，存储检查提醒有一份旧副本。

免费包放进私有仓库的 free 位置后，买家仍从本站拿文件。本站用站长令牌在服务器上读取，下载地址里不出现仓库和令牌。收费包继续走现有的短时授权地址。

应用还没绑定时，免费或收费的托管上传都停下来，提示先绑定。不退回某个全局默认仓库，也不再把收费包悄悄留在本站。外链本身是公开 HTTPS 时，仍按现在的方式拉取，不带令牌；拉取成功后写入该应用仓库里对应的位置。

## 按应用导入

导入框不再手填仓库，也不再有默认仓库名。

- 未绑定：空状态，去绑定。不列出任何发布。
- 客户安装包只读 `client/`。插件按价格读 `plugins/free/` 或 `plugins/paid/`。模板同理。
- `latest.json` 或包内清单的 `appKey` 必须等于这个应用。缺少标识：「安装包清单里没有应用标识」。对不上：「这个安装包属于另一个应用」。
- 版本必须新于该应用当前已发布的最新版。相同：「已经有这个版本」。更旧：「版本不比当前已发布的新」。
- 核对校验码。导入中按钮不可重复点。成功后表单回填版本、说明和校验值，仓库地址改成新的对象键。

## 审计

写入已有的 `source_audit_logs`，目标类型 `app_repo`，目标用 `appKey`。动作包括：绑定、创建仓库、创建应用时仓库失败、只切换、迁走、迁走失败、解绑被阻止、解绑、改价搬移、旧副本删除失败。

明细是中文句子，带应用、仓库、件数。不含令牌。仓库绑定页有「变更记录」，软件目录里原有的审计列表也能看到这些动作。

## 官网迁移，并去掉写死的默认仓库

只在官网站点、且「授权系统」这个应用还没有绑定、且存储管理里已经有收费仓库时，出现一次迁移，不在升级时静默改写。

预览列出四类件数：收费插件、收费模板、该应用的免费包、客户安装包。确认后：

1. 把现有收费仓库绑给「授权系统」这一个应用，不新建第二个仓库，也不绑到其他应用。
2. 收费插件复制到 `plugins/paid/`，收费模板复制到 `templates/paid/`。
3. 该应用已托管的免费包复制到对应的 free 位置。
4. 客户安装包复制到同一个仓库的 `client/`，并写入带 `appKey` 的 `latest.json`。
5. 每份都核对校验码。任一份失败则不改绑定、不改已有地址。
6. 全部通过后才更新地址和绑定。旧发布保留，不自动删除。

其他应用保持未绑定。客户站不出现这次官网迁移，也不种入任何固定仓库。客户站升级只显示「尚未按应用绑定」。

迁移完成后，运行时不再使用写死的客户仓库或收费仓库作为导入和上传的默认值。绑定缺失就是缺失。本站程序的在线更新仍使用它现在的来源，不读绑定表。

## 开发者端

导入接口保持不挂载，调用结果仍是找不到接口。上传根据条目所属应用找到绑定，用站长令牌写入对应位置。没有绑定时上传失败并说明原因。开发者页面看不到仓库名和令牌。

## 和字面要求不同的四处

1. 五个位置在界面上用目录名，GitHub 上用发布标签前缀。原因是现有驱动写的是 Release 附件，做成 git 提交会另起一套存储。
2. 已发布版本依赖该仓库时，解绑直接不可用，而不是警告后仍能解除。草稿才只警告。
3. 迁走和改价都是先复制、核对、再改记录。删除旧文件是核对成功之后的另一步，失败只提醒。
4. 检查放在现有「存储检查」，不新开「系统监控」。升级时不给每个应用自动建库。

## 弹窗规格

全站表单、确认和危险操作共用一个 `AppDialog`。它只负责宽度、标题栏和底部按钮顺序，外壳用 Element Plus 已有的 `ElDialog` 或 `ElDrawer`，不自己画一层遮罩，也不引入新的界面库。手机上的长表单用抽屉，短确认仍用对话框。页面不再自己写宽度和标签宽度。

宽度四档，手机一律用 `calc(100vw - 32px)`，不超过该档：

| 档 | 宽度 | 用于 |
| --- | --- | --- |
| sm | 420 | 确认、危险操作、支付 |
| md | 520 | 字段很少的表单、绑定已有仓库 |
| lg | 640 | 标准表单。创建应用是这一档的参照 |
| xl | 760 | 里面有表格或长文本的结果 |

标题栏高 56，标题 16、左对齐，关闭在右。多步用 `ElSteps`，放在标题栏下方。正文左右 20，区块之间 16。表单用 `ElForm`：电脑上标签右对齐、宽 96，手机上 `label-position="top"`。

底部按钮靠右。次要在左，主按钮在最右。危险操作的主按钮是红色，文案用动词本身，例如「解除绑定」，不用「确定」。只有一个「关闭」时，它是次要按钮，不涂成主色。底部若有「全部展开」这类工具按钮，放在左侧，和右侧的取消、主按钮分开。

证书失败仍是安装菜单里的终端输出，不收进这个弹窗。全局搜索、锁屏、广告弹层不是表单或确认，保持各自的外壳。

需要迁到 `AppDialog` 的，是下面审计里那些产品弹窗，以及现在用 `ElMessageBox` 做的确认、填写原因。创建应用的第 2 步按这套参照实现，绑定、更换、解绑、存储编辑用同一套，不再各画一个。

## 边界明细

字段错误写在字段下面，对话框保持打开，不另弹一条成功或失败提示。需要人处理的失败写在对话框正文里。只有成功才用顶部一条短提示，几秒后自己消失。

提交前能判定的错误（格式、本地冲突、令牌、公开仓库）不创建应用。应用行已经写入之后，只有远程创建或绑定记录失败才留下未绑定应用，并给出重试。

| 类别 | 规则 | 确切文案 | 之后停在哪 |
| --- | --- | --- | --- |
| 字段校验 | 应用名称为空。沿用现有文案。 | 请输入应用名称 | 停在第 1 步，不创建应用 |
| 字段校验 | 应用名称去掉首尾空格后超过 100 个字符。 | 应用名称不能超过 100 个字符 | 停在第 1 步，不创建应用 |
| 字段校验 | 选择自动创建或绑定已有，但仓库为空。 | 请填写仓库，格式为 所有者/仓库 | 停在第 2 步，不创建应用 |

## 组件

只用现有的 Element Plus，不新增界面库。`AppDialog` 不是另一套视觉，只是把按钮顺序和宽度收到一处，再渲染下面这些组件。

| 界面 | 组件 | 理由 |
| --- | --- | --- |
| 创建应用、更换、迁移，手机 | `ElDrawer`，`size="100%"` | 步骤和表单一屏放不下。项目里版本详情、开发者目录已经用抽屉。短确认不改成抽屉 |
| 创建应用、更换、迁移，电脑 | `ElDialog` lg | 桌面宽度够，对话框能同时看见背后的列表 |
| 解绑、放弃更改、令牌说明 | `ElDialog` sm | 只有一句决定，抽屉过重 |
| 创建应用的两步 | `ElSteps` | 库里的步骤条。两步用横向，不用自己画文字步骤 |
| 三个仓库选项 | `ElRadioGroup` 加带边框的 `ElRadio` | 单选是表单控件。选中项下面放该选项的字段 |
| 应用名、自动创建的仓库名、校验错误 | `ElForm`、`ElFormItem`、`ElInput` | 错误文案走表单校验，显示在字段下。主按钮用 `ElButton` 的 `loading` |
| 绑定已有仓库 | `ElSelect`，`filterable` | 从令牌能看见的私有仓库里搜，避免手写错斜线。自动创建的新名字仍用输入框，因为仓库还不存在 |
| 令牌缺失、导入进行中 | `ElAlert` | 页面里已经用它做说明条，不自己画色块 |
| 解绑影响、更换预览、迁移预览 | `ElDescriptions` | 是几行确认信息，不是数据表。手机一列，电脑两列 |
| 创建成功、仓库失败但应用已在 | `ElResult` | 结果页用库里的结果组件。成功用 success。部分成功用 info，失败用 error。不用 warning，避免主题里的橙色图标 |
| 空列表、没有发布、没有检查记录 | `ElEmpty` | 与应用列表、更新页的空状态相同 |
| 成功提示 | `ElMessage` | 全站短提示已经是它。不自己做一条浮层 |
| 仓库绑定页的应用列表、存储检查 | 现有表格 | 这是列表页，不是确认。确认框里不再嵌一套自定义表格 |

## 失败时统一规则

- 先复制，核对一致，再改数据库。
- 不在核对前删除来源。
- 不删除远程仓库。
- 令牌只存在存储管理的密文里。
- 一个应用同时只有一条有效绑定。
- 本站在线更新不读这张表。
