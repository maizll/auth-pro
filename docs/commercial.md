# 商业版

免费版只限制一件事：最多创建 1 个授权应用。已经存在的应用不会被删除或停用，授权校验 `POST /api/license/verify` 也不看商业版。商业版不限应用数量，有效期内官方付费插件和首页模板显示为已包含，可一键安装，不会在升级后自动全部安装。

界面上的限制必须同时有图标和文字，使用共享组件 `CommercialMark`（默认火箭图标，颜色跟随后台主题主色）。不能只禁用按钮，也不能只弹出一句没有图标的报错。

| 位置 | 表现 |
| --- | --- |
| 顶栏右上角 | 未开通是全圆角小胶囊：浅蓝底、主题蓝字、钻石图标、「免费版」，字号 12px，高 26px。点击在当前页弹出购买窗口，不跳转商店。已开通是实心主题蓝胶囊：白字、皇冠图标、「商业版」，右侧 12px 灰色字写到期日期或「永久授权」。点击打开授权详情卡。源站连不上但仍在宽限内时，胶囊换成浅橙「商业版」「待校验」。手机上胶囊和到期时间都保留。语言、主题设置和暗色模式收进头像菜单 |
| 应用管理的「新增应用」 | 免费版按钮旁显示火箭和「免费版仅支持 1 个授权应用，升级商业版可创建多个」。商业版有效时这句话消失 |
| 免费版已经有应用 | 应用页顶部提示条，带同一句话和「升级商业版」。这个按钮打开顶栏同一个购买窗口。商业版有效时这条提示消失 |
| 点击被挡住的操作 | 弹出说明，带图标和文字。免费版按钮是「升级商业版」；有期限的商业版是「续费」；永久商业版是「查看授权」。都打开同一个窗口，不跳页 |
| 后端返回「该功能需要商业版」 | 多应用限制仍是全局通知，带图标、说明，以及同上的按钮 |
| 未购买的付费插件或模板 | 卡片按钮写成「购买 ¥X」。点启用或安装打开同一个购买窗口。窗口先显示登记信息：图标（没有则用名称首字加主题色底）、名称、官方或第三方、版本、开发者、简介最多两行，「查看详情」展开全文，缺字段不显示。已绑定后，官方条目左右两张卡片（手机上仍并排）：默认「单独购买此插件」或「单独购买此模板」，写明价格和期限，小字「只解锁这一个插件 / 模板」；右侧「商业版套餐」带「推荐」角标，价格和期限取源站排序第一的套餐，小字「含全部官方付费插件和模板，应用数不限」。下面始终展示对照表。第三方或「所有人都需购买」的条目只有单独购买，说明「由第三方开发者提供，商业版不包含，需要单独购买」，不放套餐卡和对照表。已经是商业版且该条目已包含时不弹购买，直接启用。支付方式只显示已开通的，按钮是「立即支付 ¥金额」。付款区仍是二维码、应付金额、倒计时和付款页。付完后刷新权益并继续启用 |
| 商店角标「商业版免费」「已包含」 | 图标加文字 |
| 应用商店 | 不显示版本状态。免费版、商业版、到期和待校验只在顶栏。条目上的「商业版免费」「已包含」仍标在对应插件或模板上 |

顶栏「免费版」胶囊和限制提示里的「升级」「续费」打开同一个购买窗口，单独购买插件或模板也用这个窗口，不另做第二套。从顶栏进来时，窗口顶部是蓝色渐变横幅，标题为「升级商业版，解锁全部能力」。单品窗口改为插件信息块，不放这条横幅。账号栏在源站核对成功（`sourceVerified`）后同一行显示脱敏账号和「用户」或「代理商」小标签，不换行，过长省略。「管理授权」在新窗口打开 `https://auth.maizll.com` 上该身份的「我的授权」，「切换绑定」先确认再解除当前绑定。未绑定是浅橙条「未绑定账号，绑定后才能购买」；绑定已删除或令牌失效是「之前的绑定已失效，请重新绑定」。右侧「注册账号」在这个窗口里注册：邮箱、6 位邮箱验证码、用户名、至少 6 位密码，手机号选填。源站开启行为验证时，获取验证码前先完成验证。注册成功后用新账号自动绑定，只提示一次「注册并绑定成功」，然后进入套餐或支付。可以切回「已有账号，去绑定」。下面一行写出单独购买价格，然后是身份、账号、密码和「登录并绑定」。主动切换绑定不显示失效文案。连不上源站时保留本地快照，并提示尚未经源站确认。官方单品和套餐窗口都展示对照表，手机上仍是三列，不收起。对照表只列代码里真实存在的差别：免费版只能新建 1 个授权应用，商业版不限；官方付费插件和首页模板在免费版需单独购买，商业版写「全部包含」（有效期内视为已包含，仍需点一次安装，不会自动全装）。套餐窗口在表下保留说明：已经存在的应用不会删除，授权校验不看商业版，升级后也不会自动安装全部插件和模板。对照文案在 `frontend/src/utils/commercial.ts` 的 `commercialCompareRows`。源站没有原价字段，套餐卡片只显示现价，不编造划线价。单品窗口里排序第一的套餐做成「商业版套餐」卡片，右上角「推荐」。按钮文案是「立即支付」加上当前卡片的金额。

未绑定账号时先登录（密码只转发，不保存），源站回调本站域名完成校验后再选择套餐卡片。源站开启了多种在线收款时，窗口里可以切换，选中框用主题蓝；没有配置时不显示切换，由源站用第一种收款方式。付款沿用原来的商业版订单接口，窗口内显示二维码、应付金额、剩余时间和「安全支付」说明，也可以打开付款页。成功后有轻量庆祝动画，并提示「已升级为商业版」（续费则提示「商业版已续费」），关闭后顶栏和限制提示立即更新。源站未配置套餐、网络不通、支付失败或等待超时都会用中文说明，不会停在空白窗口。手机上这个窗口全宽，内容不横向溢出。永久商业版点顶栏带「永久授权」的「商业版」胶囊，打开授权详情卡，不再生成付款码。详情卡可以「立即刷新」，并显示上次校验时间。

## 商业版套餐不进授权购买页

标记为「作为本站商业版出售」的应用，套餐只用于顶栏「升级商业版」。用户端和代理端的授权购买页不会列出这些套餐，购买接口也会拒绝，并提示到顶栏购买。付款回调和顶栏订单走同一条开通：写入商业版权益，买家站点下次拿到签名快照后去掉单应用限制。

如果以前有人在授权购买页买过这类套餐，订单已支付但没有商业版权益。授权列表和订单列表顶部会提示，点「一键补发商业版授权」补上。已经开通过的再点不会多发一份。

## 买方怎么升级

1. 点管理后台顶栏右上角的「升级商业版」。购买网站固定是 `https://auth.maizll.com`，后台不显示这个地址，也不能在页面上修改。本站域名按当前访问自动识别：用正式的 https 域名打开后台即可。请求来自本机反代时，采用转发后的域名；宝塔常见的 `Host` 加 `X-Forwarded-Proto: https`（可以没有 `X-Forwarded-Host`）也会识别成功。识别到本机、内网或 http 时，窗口只提示「请用正式的 https 域名打开后台后再试。本机、内网或 http 地址不能用来绑定。」没有填写框。
2. 用源站的用户或代理商账号登录。源站会请求 `https://<域名>/api/v1/public/station-verify/<nonce>`，不跟随重定向，并拒绝内网 DNS、IP、localhost。
3. 选择该应用在套餐管理里已启用、且价格大于 0 的套餐，扫码支付。时长为 0 的套餐是永久。订单号以 `PP` 开头。支付成功后源站在查单响应里返回新的 Ed25519 签名快照，本站保存后立即生效。
4. 官方付费插件、模板显示「已包含」，点一次安装。下载票 10 分钟有效，下载时再次核对权益。免费版可以在应用商店单独购买某一条，不必先升级商业版。开发者付费条目不包含在商业版里，窗口会写「商业版不包含此项」。未购买就启用时，接口返回「该插件需要购买后才能启用」或「该模板需要购买后才能启用」，并带上条目种类、编号、价格和是否仅单买。

正式程序的购买网站只有 `https://auth.maizll.com`，没有环境变量、配置文件或数据库入口。升级时会删掉 `system_configs` 里旧的 `store_source_base`、`store_site_url` 和 `store_trust_proxy`。`PUT /api/store/settings` 即使带上这些字段也只返回成功，不会写回。自动化测试要改源站地址时，只在 `backend/handler` 的 `_test.go` 里给包内变量 `buyerSourceBaseForTest` 赋值。双站端到端脚本另用 `go build -tags e2e` 编译测试二进制，该标签不进入发布包。

快照约每 6 小时刷新。连不上源站，或源站响应无法解析时，按快照里的宽限天数继续保持商业版，默认 7 天。源站对已删除的授权或绑定返回 `revoked: true` 和原因（如 `license_deleted`、`binding_deleted`、`binding_revoked`）。买家只认这些字段，不看中文提示。下单、查单、刷新、安装和下载只要收到这类原因，就清掉本机绑定凭据和快照，效果同解除绑定。购买网站仍是 `https://auth.maizll.com`。本站域名仍按这次访问自动识别。接口返回「之前的绑定已在源站删除，请重新绑定账号后继续购买」，并带上 `rebind: true` 和具体原因。业务码是 400，避免被当成管理员登录失效。购买窗口收到后回到绑定步骤；绑定成功后回到刚才选的套餐或单品继续付款。打开购买窗口时会向源站核对绑定。源站确认有效才提示已绑定并进入套餐；绑定已删除或令牌失效会清掉本机凭据，只显示重新绑定。连不上源站时保留本地快照。还没开通商业版不再当成绑定已删除。已绑定账号用账号栏的「切换绑定」换账号，不再使用黄色大按钮。主动切换绑定不会提示「之前的绑定已在源站删除」。本地已经没有令牌时，解除绑定不再请求源站；源站回答绑定已删除或令牌失效时仍按解除成功处理。源站确认和状态接口带回登录账号与身份；确认响应没有名字时，用这次提交的账号写入快照。之后刷新如果没带回名字，保留快照里原来的账号。同域名上已删除、已吊销或已过期的旧授权不再占用域名，可以新建绑定；别的账号下仍有效的授权才会提示「域名已绑定」。已删除和吊销不进宽限。查询失败、刷新过于频繁这类源站仍在线的错误，不改本地快照。在源站删除授权时，商业版权益和站点绑定按吊销写入；带商业版的授权在删除前会提示「该授权带有商业版，删除后对应站点将失去商业版」。如果这份快照就在本机，顶栏马上回到「升级商业版」。源站身份本身不会让顶栏变成商业版。顶栏「商业版」弹窗和授权详情卡可以点「立即刷新」，并显示上次校验时间。域名和快照不一致时按免费版处理，顶栏回到「升级商业版」。

改密码会撤销该账号下的站点绑定（源站可关闭这项）。自助更换产品应用的域名在用户端或代理端「我的授权」里操作，每 30 天一次，管理员不限次数；旧域名上的绑定会撤销。免费更换次数和超出后的付费更换另计，30 天限制仍然生效。没有单独的绑定域名页面。

## 源站管理员

开通顺序：

1. 在「应用授权 → 应用管理」新建或编辑应用，打开「作为本站商业版出售」。全站只能有一个应用打开。换到另一个应用时会提示，并关掉原来的那个。
2. 在「套餐管理」给这个应用添加已启用、价格大于 0 的套餐。授权天数填 0 就是永久。
3. 在「支付配置」配好在线收款。
4. 应用列表会显示「商业版产品」。缺套餐、缺支付或签名密钥未生成时，点状态可以直接去处理。签名密钥也可以在这一行生成，不必再开页面。

同一弹窗里可以展开高级设置：离线宽限（1–30 天，默认 7）、改密是否撤销绑定（默认开）、商业版功能键（默认 `multi_app`，表示允许多个应用，一般不用改）。

买家绑定后如果还没有主授权，系统自动建一条不挂套餐的免费主授权。不需要再填免费套餐 ID。

收款沿用本站已配置的在线支付，不使用余额。支付完成页是源站自己的 `/store/pay-complete`。商店订单出现在「订单列表」，类型为「商业版」「付费插件」「付费模板」，页上有已支付合计。退款仍会让商业版立即失效。授予和吊销商业版在「授权列表」的行操作里，来源可以筛选「商店绑定」「商店购买」。

旧地址 `/source-station/edition` 转到套餐管理，`/source-station/store-orders` 和 `/source-station/store-revenue` 转到订单列表，`/source-station/store-licenses` 转到授权列表。

快照用 Ed25519 签名。买方只验签，改数据库不能伪造商业版。私钥只在源站本机，不要放进仓库、环境变量、聊天记录或发行包。

自 1.5.6 起，发行包源码默认内置源站公钥 `pwAizm/sOyWCu+qi8+Dl/xJr0Upuamh5u7vL3wGT14A=`。正常发布不需要再设置 `AUTH_PRO_STORE_SNAPSHOT_PUBLIC_KEY`，也不需要用 ldflags 打入公钥。源站升级到 1.5.6 后，用本机已有的 `store/snapshot-ed25519.key` 签发；买方用包内公钥验签。商业版购买与授权下发可以正常使用。

源站必须先升级到 1.5.6。升级时保留数据目录里已有的私钥文件，不要重新执行 `store-keygen`，也不要删除该文件。私钥和内置公钥不一致时，源站拒绝签发，接口返回「商店签名私钥与发行包公钥不匹配」。

如果构建时把公钥覆盖成占位符 `PLACEHOLDER_NOT_CONFIGURED` 或空字符串，行为与未配置相同：买方把每一份快照都当成无效，保持免费版，顶栏仍是「升级商业版」。源站拒绝签发，接口返回「商店签名公钥未配置，拒绝签发快照」。

更换密钥时才改公钥：

1. 在源站、数据目录所在的机器上执行（二进制名以安装目录为准，常见是 `backend/auth_pro`）。已有私钥时必须加 `--force` 才会覆盖：

   ```bash
   ./auth_pro store-keygen --force
   ```

2. 命令只打印两行：第一行是新公钥的标准 base64，第二行是中文提示。把第一行交给维护者。私钥写在数据目录 `store/snapshot-ed25519.key`，权限 `0600`。不要复制私钥，不要发到别处。
3. 维护者改源码默认值，或在构建时覆盖。两种覆盖写法等价，把 `<打印出的公钥>` 换成上一步的第一行：

   ```bash
   AUTH_PRO_STORE_SNAPSHOT_PUBLIC_KEY='<打印出的公钥>' ./scripts/build-release.sh
   ```

   ```bash
   cd backend
   go build -ldflags "-X auto_pro/handler.embeddedStoreSnapshotPublicKey=<打印出的公钥>" -o auth_pro .
   ```

4. 用这次打出来的包更新源站和买方站点。源站用本机私钥签发，买方用包内公钥验签。私钥文件留在源站数据目录，升级时不要删掉。

第三方开发者的付费条目仍然不能上架。源站管理员名下（`developer_id = 0`）的托管 ZIP 或内置交付可以上架。单件购买和第三方分成不在这一版。
